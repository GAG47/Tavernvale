# Tavernvale Development Rules

1. Codex 的职责是实现已经确定的设计，不负责自行扩展产品或系统设计。
2. 不得未经任务明确要求实现下一阶段、额外功能或“顺便优化”。
3. 如果任务要求与当前项目架构发生明确冲突，必须停止相关实现，说明问题与原因并给出可选方案，不得自行选择完全不同的架构继续开发。
4. 修改现有核心架构前，必须有明确任务依据。
5. 正式开发必须执行与本次修改相关的测试。
6. 每一次正式开发任务必须在 `docs/logs/` 新增一份独立开发日志。
7. 没有开发日志的正式开发任务视为未完成。
8. 开发日志必须记录实际发生的内容，不能简单复制任务提示词。
9. 如果实际实现与原设计或任务要求存在偏差，必须记录原要求、实际实现和偏差原因；如果没有偏差，明确写“无”。
10. 不得静默吞掉测试失败、Validator 错误或已知问题。
11. 文档必须描述当前真实实现，不得把尚未完成的计划写成已经实现。
12. 一项正式开发任务对应一份独立日志，不使用无限增长的单一日志文件替代。

## Development Log Format

每份日志使用 Markdown，并包含以下部分：

- 标题、Version、Date、Commit
- 目标
- 修改内容
- 修改文件
- 关键实现
- 测试（包括 Validator 结果，如适用）
- 已知问题
- 设计偏差
