# Formal Hydrology

- Version: v1.5
- Date: 2026-08-29
- Commit: 未提交

## 目标

在只读 v1.4 conditioned `terrain_height` 的前提下，把 Spatial Graph、v1.3 Preliminary Climate 和 `closed_basin_id` 转换为正式水文数据：Local Runoff、Flow Direction、Flow Accumulation、River Network、Strahler Order、Watershed 与 Closed Basin Inflow。

## 修改内容

- 新增正式 Hydrology 设置、数据层、生成器和 Validator。
- 直接复用 `SpatialGraph.cell_areas` 计算水量，复用与 `cell_neighbors` 对齐的 `cell_neighbor_distances` 计算实际下降坡度。
- 使用入度法拓扑排序累计水量，同时拒绝 Loop。
- 根据累计水量阈值生成 River Cell，并对河网计算 Strahler Order。
- 将通过正式流向连接的 River Cell 聚合为 River Network，输出 source、mouth、discharge 与最大 order。
- 按具体 Water Cell、World Boundary Cell 或 Closed Basin ID 分配 Watershed。
- 汇总每个 Closed Basin 的 catchment area、total inflow 与面积加权 mean temperature。
- 扩展现有 World Debug View，增加 Flow Accumulation、River Network、Watershed 模式和正式水文 Cell Inspect。

## 关键实现

### Pipeline 与正式接口

Debug 中当前数据流为：

```text
projected terrain_height ─> Preliminary Climate
          │
          └─> Hydrology Conditioning ─> conditioned terrain_height
                                               │
conditioned terrain_height + preliminary climate + closed_basin_id
                                               │
                                               └─> Formal Hydrology
```

`WorldHydrologyLayer` 正式保存：

- `local_runoff: PackedFloat32Array`
- `flow_to: PackedInt32Array`
- `flow_accumulation: PackedFloat32Array`
- `watershed_id: PackedInt32Array`
- `river_id: PackedInt32Array`
- `river_order: PackedInt32Array`
- `rivers: Array[HydrologyRiver]`
- `closed_basin_inflows: Array[ClosedBasinInflow]`

没有保存可由 `river_id >= 0` 推导的 `is_river`。

### Cell Area 与 Local Runoff

面积直接读取 Spatial Graph 已有的 Voronoi `cell_areas[cell_id]`，没有复制到 Hydrology Layer。公式为：

```text
local_runoff = precipitation × cell_area × runoff_modifier
```

默认 `runoff_modifier = 1.0`。输入和输出均验证有限且非负。

### Flow Direction

普通陆地 Cell 遍历真实 `cell_neighbors`，对每个更低邻居计算：

```text
slope = (current_height - neighbor_height) / neighbor_distance
```

选择 slope 最大的邻居；相同坡度用较小 Cell ID 确定性打破平局。Water、Boundary 和 Closed Basin Cell 分别使用 `-1`、`-2`、`-3` sentinel。普通陆地没有更低邻居会使生成失败，不能在 v1.5 中修改高度。

### Flow Accumulation

以 `local_runoff` 初始化 Float64 临时累计数组，按 `flow_to` 计算入度并使用 Kahn 拓扑顺序，每条上游贡献只向下游加入一次。最后转换为正式 `PackedFloat32Array`。拓扑处理数量不等于 Cell Count 时作为 Loop 错误。

### River Network 与 Strahler Order

唯一 River 参数为 `river_runoff_threshold = 50000.0`，单位是当前相对水量。Land Cell 的 `flow_accumulation >= threshold` 时成为 River Cell。

Strahler Order 按上游到下游的同一拓扑顺序计算：没有 River 上游为 1；最大上游 Order 出现至少两次则加一，否则保持最大值。

通过正式上下游边相连的 River Cell 组成一个 River Network，共享 `river_id`。每个 `HydrologyRiver` 保存：

- `id`
- `source_cell`：该网络中没有 River 上游、且累计水量最大的候选源头
- `mouth_cell`：下游离开 River Cell 集合的末端
- `discharge`：mouth Cell 的 accumulation
- `order`：网络最大 Strahler Order

### Watershed 与 Closed Basin Inflow

每个 Land Cell 沿 `flow_to` 解析到一个具体终点。相同 Water Cell、相同 Boundary Cell 或相同 Closed Basin ID 共享 Watershed ID；Water Cell 自身不分配 Land Watershed。

Closed Basin Inflow 对最终进入该 basin 的所有 Land Cell 各累计一次 `local_runoff` 和 `cell_area`，因此不会重复使用已经累计过的下游水量。Mean temperature 使用 `temperature × area / catchment_area`。

### Debug

- `F`：Flow Accumulation，使用 `log(1 + accumulation)` 非线性色阶，显示 Min、Mean、Median、P75、P90、Max。
- `N`：River Network。现有 `R` 已用于 Seed+1，因此使用 N。颜色按 Strahler Order 增强，显示 River Count、River Cell Count、最大 Order 和最大 Discharge。
- `W`：Watershed，使用基于 Watershed ID 的确定性颜色。
- Cell Inspect 增加 Local Runoff、Flow To、Flow Accumulation、River ID、River Order、Watershed ID 与 Closed Basin ID。

## 已知问题

- 当前水量仍是相对单位，不代表 mm/year 或 m³/s。
- River Network 当前按正式上下游边的连通树聚合；没有河宽、视觉曲线、季节流量或侵蚀。
- Watershed 的 Ocean Outlet 以具体 Water Cell 区分，不把整片连通海洋合并成单一流域出口。
- 未实现可选 Lake 子阶段。当前 v1.4 正式接口不包含 spill height，v1.5 也没有已确定的 evaporation/lake 参数；核心 Closed Basin Inflow 已完成，避免为 Lake 扩张设计。

## 设计偏差

无。Lake 子阶段在任务中是核心水文稳定后的可选项，本次按允许范围停在 Closed Basin Inflow。未修改 Spatial Generator、Composition Generator、TerrainHeightProjector、Climate Generator 或 HydrologyConditioner，也没有重新运行 Conditioning、修改 terrain_height 或实现 v1.6 消费者。
